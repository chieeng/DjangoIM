4. DATA FLOW: ADDING A ROOM (Admin/Staff)
================================================================================

STEP 1 - User navigates to Add Room
  Trigger : Clicks "Add Room" in navbar Admin menu OR dashboard Quick Actions
  Template: templates/rooms/dashboard.html -> action-card link (line 295)
            templates/base.html -> Admin dropdown (line 54)
  URL     : /rooms/addNewRoom/

STEP 2 - Django routes the request
  File    : rooms/urls.py
  Matches : path('addNewRoom/', views.add_room, name='add_room')

STEP 3 - View checks access and builds form (GET request)
  File    : rooms/views.py
  Function: add_room (line 115)
  Actions :
    - @login_required -> checks session, redirects to login if not authenticated
    - @staff_or_admin_required -> checks role_type, redirects if customer
    - Creates empty RoomForm()
    - Passes form + title to template

STEP 4 - Form is rendered
  File    : templates/rooms/addNewRoom.html
  Block   : <form method="post" enctype="multipart/form-data"> (line 15)
  Fields shown (from RoomForm in rooms/forms.py):
    - room_number    (TextInput)
    - floor_number   (NumberInput)
    - room_type      (Select -> queries RoomType table)
    - status         (Select -> STATUS_CHOICES)
    - price_per_night(NumberInput)
    - image          (FileInput -> stored in media/rooms/)

STEP 5 - User submits form (POST request)
  File    : rooms/views.py
  Function: add_room (line 115)
  Actions :
    - form = RoomForm(request.POST, request.FILES)
    - form.is_valid() runs validators:
        * room_number must be unique
        * floor_number between 1-50
        * price_per_night >= 0
    - If valid: form.save() -> INSERT INTO rooms (...) in MySQL
    - messages.success() -> flash message shown on next page
    - redirect to rooms:index (dashboard)
    - If invalid: re-renders form with error messages

STEP 6 - Room saved to database
  Table   : rooms (MySQL hotel_db)
  Auto set: created_at, updated_at timestamps
